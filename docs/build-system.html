Build System

This repository is a fork of the OP-TEE build.git project: every platform has one top-level makefile, named after the SoC, and a directory of the same name. The Qualcomm boards follow that layout and share what is not board specific. This page describes the parts all boards have in common; the board pages describe the rest.

Manifests

Each board has a manifest in qcom-manifest. It includes the shared common.xml (OP-TEE client and tests, Buildroot, the OP-TEE examples), replaces the Linux and OP-TEE trees with the ones the board needs, adds TF-A and U-Boot, and pins every tree to a revision. The build project links the board makefile to build/Makefile, so make in build/ builds that board: 

repo init -u https://github.com/ldts/qcom-manifest -m <platform>.xml
repo sync -j4 --no-clone-bundle

Images

Every board ends up with three images, for the partitions that hold the open boot chain and the OS. The Qualcomm boot firmware in front of them (XBL and the firmware it loads) is the stock release; on the IQ-9075 EVK flash-loader writes it from the public boot binaries that make fetch-blobs downloads, on the VENTUNO Q it is left in place.

Boardtz partitionuefi partitionefi partition
IQ-9075 EVK tz.mbn: U-Boot SPL with a SWIV segment, qtestsign signature uefi.elf: FIT image with BL31, OP-TEE and U-Boot proper, loaded by the SPL efi.bin: FAT32 ESP with the UKI
VENTUNO Q tz.mbn: TF-A BL2 (or U-Boot SPL with TZ_IMAGE=u-boot-spl) with a SWIV segment, QTI signature fip.elf: FIP with BL31, OP-TEE and U-Boot in an ELF, qtestsign signature, loaded by XBL (uefi.elf, a FIT, for SPL) efi.bin: FAT32 ESP with the UKI

Signing explains what XBL checks on these images and Flashing how they are written.

Linux, rootfs and UKI

  • Linux is built from the arm64 defconfig with OP-TEE enabled, CONFIG_MODULES off (everything the board needs is built in) and EFI_ZBOOT, which produces vmlinuz.efi. It runs at EL2: the board DTB is combined with the SoC's EL2 overlay.
  • Buildroot builds a small rootfs as a gzip-compressed cpio, with the OP-TEE client (tee-supplicant), xtest and the OP-TEE examples. Board files come in through BR2_ROOTFS_OVERLAY: qcom/overlay, then the board's own overlay.
  • ukify bundles the kernel, the DTB, the rootfs as initramfs and the kernel command line into one EFI binary, the UKI, using the stub in qcom/ukify/. efi.bin is a FAT32 image holding it as EFI/Linux/uki.efi; U-Boot starts it through UEFI (on the IQ-9075 EVK through systemd-boot, installed as EFI/BOOT/bootaa64.efi; on the VENTUNO Q the UKI itself is EFI/BOOT/bootaa64.efi).
  • The console is the Qualcomm GENI UART, ttyMSM0 at 115200 8N1.

Adding a board

  1. A manifest <platform>.xml in qcom-manifest that links <platform>.mk to build/Makefile.
  2. <platform>.mk and <platform>/ here, using qcom/ for the shared files and the target names above.
  3. A board page and a quick start in docs/, a row in the tables of the concept pages, and the pages in the NAV list of docs/_rtd.js (checked by node --test docs/_rtd.test.js).
