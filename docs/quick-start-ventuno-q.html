VENTUNO Q Quick Start

From an empty directory to an Arduino VENTUNO Q running TF-A, OP-TEE, U-Boot and Linux built from source. The board page explains the boot chain and the images.

Get the sources and build

  1. Install the build host packages, repo and qdl: Host Setup.

  2. Initialize the workspace and sync it:

    mkdir sandbox.monaco && cd sandbox.monaco
repo init -u https://github.com/ldts/qcom-manifest -m monaco.xml
repo sync -j4 --no-clone-bundle

  3. Build the toolchains, then the images:

    cd build
make -j8 toolchains
make all      # monaco/output/: bl2.elf, fip.elf, efi.bin

    make all runs bootimage (OP-TEE, U-Boot, TF-A, fip.elf) and efi (Linux, Buildroot, the UKI and efi.bin). The first build takes the longest: Buildroot builds its host tools and the whole rootfs.

  4. Make the signed TZ image, tz.mbn. With access to the QTI remote signing service and the Qualcomm signing package:

    make tz-qti-sign SECTOOLS=<path to sectools> QTI_SIGN_DIR=<signing package> \
     CASS_CAPABILITY=<capability> \
     QTI_SIGN_SERVER_URL=<server URL> QTI_SIGN_SERVER_PORT=<port>

    Without it, copy a signed tz.mbn built from the same TF-A tree to monaco/input/tz.mbn. A qtestsign signature does not boot on this board (see Signing).

Flash

  1. Copy the eMMC firehose programmer from the board's stock software image to monaco/input/prog_firehose_ddr.elf (monaco/input/README.md gives the SHA-256 of the one this build was tested with).

  2. Connect the board's USB port to the build host and put the board in EDL mode (it shows up as 05c6:9008 in lsusb; the board's documentation describes how to get there).

  3. Write the boot chain and the kernel image:

    make flash-loader    # tz_a, tz_b, uefi_a, uefi_b
make flash-kernel    # efi

    Only these five partitions are written; XBL and the rest of the stock firmware stay in place.

Boot

  1. Open the console (ttyMSM0 on the board, 115200 8N1) and power the board on. TF-A, OP-TEE, U-Boot and Linux each print the build's BUILD_ID (see monaco/output/build-info.txt), and so does the login banner. Log in as root, without a password.

  2. Check OP-TEE from Linux:

    xtest

make help lists every target and variable. The kernel configuration is generated once; after changing the options in monaco.mk, run make linux-defconfig.
