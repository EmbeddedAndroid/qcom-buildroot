Signing

XBL, the Qualcomm boot loader, loads the image in the tz partition as a signed ELF (MBN) image and hands control to it. That image is the first stage of the open boot chain, so the build signs it in the form the board's XBL accepts, also on boards where secure boot is not enabled. Which form that is depends on the SoC.

The TZ stage

The tz partition holds the first open-source stage of the chain. It runs at EL3 and loads the rest: TF-A BL31, OP-TEE (BL32) and U-Boot (BL33).

SWIV segment

XBL expects the TZ image to carry a SW image version (SWIV) segment at a SoC-specific address. qcom/security/swiv_build_utility.py adds it to the ELF before signing: 

python3 qcom/security/swiv_build_utility.py <output.elf> <input.elf> <chipset>
Chipset argumentSWIV segment address
lemans0x1c042000

qtestsign

qtestsign signs an image with a test certificate chain it generates itself. It runs locally and needs no Qualcomm account. The build clones it into qtestsign/ next to build/ the first time it is needed.
