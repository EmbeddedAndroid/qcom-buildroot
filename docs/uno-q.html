Arduino UNO Q

The Arduino UNO Q is built around the Qualcomm QRB2210 (Agatti) SoC. It boots from eMMC.

agatti.mk builds for it:

  • the open boot chain: TF-A and OP-TEE with the Agatti support under review, and U-Boot;
  • the Arduino Linux kernel of the UNO Q Yocto image with a Buildroot initramfs, packed in a UKI.

Boot chain

XBL -> TF-A BL2 (tz) -> BL31 -> OP-TEE -> U-Boot (uefi) -> UKI (efi): Linux at EL2
  1. XBL loads TF-A BL2 from the tz partition into the IMEM TZ window, and the FIP, wrapped in an ELF, from the uefi partition.
  2. BL2 loads BL31, OP-TEE (BL32) and U-Boot (BL33) from the FIP.
  3. U-Boot starts the UKI from the ESP through UEFI: bootefi bootmgr finds it as EFI/BOOT/bootaa64.efi.

The Yocto configuration builds most drivers as modules. linux-modules installs them in the rootfs, and the S05modules init script loads those listed in /etc/modules (LINUX_MODULES_LOAD, by default the USB PHY drivers phy-qcom-qusb2 and phy-qcom-qmp-usbc, which the UNO Q needs). Linux runs at EL2 with the board DT.

Build

make toolchains
make all                         # bl2.elf, fip.elf, efi.bin in agatti/output/
make tz-qti-sign QTI_SIGN_DIR=... CASS_CAPABILITY=... \
     QTI_SIGN_SERVER_URL=... QTI_SIGN_SERVER_PORT=...   # tz.mbn

tz-qti-sign signs bl2.elf with Qualcomm sectools through the QTI remote signing service. The Agatti TZ security profile (agatti_tz_security_profile.xml in QTI_SIGN_DIR) comes from the Qualcomm signing package. XBL boots only a QTI-signed TZ image; without one in agatti/output/, flash-loader uses a QTI-signed tz.mbn placed in agatti/input/.

Each make invocation stamps BUILD_ID (default agatti-<UTC date-time>) into the TF-A build string, the OP-TEE version, the U-Boot and Linux versions and /etc/issue; the build fails if an image lacks it, and agatti/output/build-info.txt records the identifier of each image.

The kernel is built with CONFIG_MEMTEST: memtest=<N> on the command line runs N patterns over all free memory early in the boot (see the VENTUNO Q page).

Flash

qdl writes the images by partition name; the partition table and everything else on the eMMC stay as they are. The firehose programmer comes from the board's stock software image and goes in agatti/input/ (or set FIREHOSE); see agatti/input/README.md. 

make flash-loader    # tz_a, tz_b <- tz.mbn; uefi_a, uefi_b <- fip.elf
make flash-kernel    # efi <- efi.bin

flash-lava writes the same partitions on a UNO Q in the LAVA lab (device type qrb2210-arduino-imola), as on the VENTUNO Q, at their place in the UNO Q eMMC layout (qcom-ptool qrb2210-unoq/emmc-16GB-arduino).

KVM

Linux runs at EL2. The Cortex-A53 has no VHE, so KVM runs in nVHE mode (/dev/kvm). The rootfs carries kvmtool, the KVM unit tests in /opt/kvm-unit-tests and a small Linux guest in /opt/kvm-guest, as on the VENTUNO Q.
