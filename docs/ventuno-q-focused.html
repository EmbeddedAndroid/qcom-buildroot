Platform Overview

SoC

  • Qualcomm QCS8275 (Monaco)
  • 4 × Cortex-A78C, 4 × Cortex-A55
  • Adreno 623 GPU
  • Hexagon ADSP, CDSP and GPDSP

Board

  • Arduino VENTUNO Q
  • eMMC storage
  • Serial: ttyMSM0 (UART 7)
  • HDMI (ADV7535 bridge) and DisplayPort
  • USB Type-C, EDL / qdl flash

Software Stack

  • TF-A BL2 (TZ stage), or U-Boot SPL
  • TF-A BL31 (EL3 Secure Monitor)
  • OP-TEE OS (BL32)
  • U-Boot (BL33 / UEFI)
  • Linux + Buildroot initramfs (UKI)

Notable specifics: XBL only accepts a QTI-signed TZ image, so the repo ships a signed BL2 (monaco/input/tz.mbn). U-Boot moves the boot to the first Cortex-A55.

Build Outputs Three flashable images

1 · tz.mbn

tz_a, tz_b · QTI-signed TF-A BL2

  • SWIV-annotated, then QTI-signed with sectools (make tz-qti-sign)
  • Or the signed BL2 the repo ships, monaco/input/tz.mbn
  • Runs at EL3 in system IMEM at 0x14680000

2 · fip.elf

uefi_a, uefi_b · FIP in an ELF, qtestsign signature

  • XBL loads it to 0xaf000000
  • TF-A BL31 for 0x1c200000

  • U-Boot (BL33) for 0xaf400000

efi · FAT32 ESP with 512-byte sectors

  • EFI/BOOT/bootaa64.efi: UEFI fallback entry
  • EFI/Linux/uki.efi: the Unified Kernel Image, with
  •   • the kernel (EFI_ZBOOT)
  •   • monaco-arduino-monza.dtb + monaco-el2.dtbo
  •   • the Buildroot initramfs and the command line

UKI · EL2

BL2 loads BL31, OP-TEE and U-Boot from the FIP XBL placed at 0xaf000000. OP-TEE stays resident at S-EL1 while U-Boot loads Linux.

Control DTB · U-Boot

qcom/monaco-arduino-monza from U-Boot's dts/upstream, set by the board fragment arduino-ventuno-q.config.

Linux DTB · monaco-arduino-monza + EL2

The board DTB with the Monaco EL2 overlay (monaco-el2.dtso) applied, so Linux runs at EL2. Both are in mainline since v7.1. Bundled into the UKI, no separate flash step.

Boot Sequence

PBL · Primary Boot Loader Hardware ROM in the SoC. Loads XBL from eMMC. Cannot be modified.
XBL · eXtensible Boot Loader Qualcomm proprietary. Initialises DDR, clocks and power rails. Loads the tz image into system IMEM and the uefi image to DDR at 0xaf000000.
QTI signature check on tz.mbn XBL checks the QTI signature of the TZ image even with secure boot disabled, then starts it at EL3.
TF-A BL2 (tz.mbn) @ 0x14680000 Runs at EL3 in system IMEM. Loads BL31, OP-TEE and U-Boot from the FIP and starts BL31.
TF-A BL31 · Secure Monitor @ 0x1c200000 Runs at EL3. Starts the CPUCP firmware XBL loaded and brings up the Cortex-A55 clock domain through it. Starts OP-TEE, then U-Boot.
BL32 · OP-TEE OS @ 0x1c300000 Initialises in Secure EL1 and returns to BL31. Stays resident for Trusted Applications and the PAS service that starts the DSPs.
BL33 · U-Boot (UEFI) @ 0xaf400000 Entered on CPU0, a Cortex-A78C, at EL2. Starts the first Cortex-A55 (MPIDR 0x10000) with PSCI CPU_ON and turns CPU0 off.
UEFI boot · bootaa64.efi bootefi bootmgr finds the UKI on the ESP as EFI/BOOT/bootaa64.efi and starts it.
Linux kernel (EL2) Boots on the Cortex-A55 with the board DTB and the EL2 overlay. All eight CPUs come up at EL2, with KVM.
Buildroot initramfs BusyBox init, tee-supplicant, the FastRPC daemons, ALSA tools and qcom-tests.

Projects · 1 of 4

U-Boot BL33 / UEFI, and SPL as an option

U-Boot: BL33 / UEFI
  • qcom_defconfig + tfa-optee.config + arduino-ventuno-q.config.
  • BL2 loads it from the FIP to 0xaf400000; it runs at EL2.
  • CONFIG_BOOT0_QCOM_BOOT_CPU: moves the boot to the Cortex-A55 at MPIDR 0x10000.

Boot behaviour

  • Reads the ESP (FAT32 efi.bin).
  • bootefi bootmgr starts EFI/BOOT/bootaa64.efi, the UKI.
  • Linux runs at EL2 once the UKI starts it.
SPL: optional TZ stage
  • TZ_IMAGE=u-boot-spl builds SPL (qcom_monaco_spl_defconfig) as the TZ image instead of BL2.
  • Runs at EL3 where XBL enters the TZ image: 0x14680000 to 0x1469a000.
  • Reads a FIT with BL31, OP-TEE and U-Boot at 0xaf000000, where XBL loaded it: no storage driver.
  • Needs a QTI signature, like BL2.
Projects · 2 of 4

TF-A BL2 and BL31

What it is

ARM Trusted Firmware supports Monaco as a SoC of its own under plat/qti/hoya. BL2 is the first open-source stage and BL31 is the runtime Secure Monitor at EL3, resident for the life of the system.

Build

  • PLAT=monza SPD=opteed, targets bl2 and fip.
  • BL2 goes to tz.mbn; BL31, OP-TEE and U-Boot go to the FIP.
  • With SPL as the TZ stage, only bl31 is built.
Role in the boot chain
  • BL2 at 0x14680000 loads the FIP images and starts BL31.
  • BL31 at 0x1c200000 starts the CPUCP firmware and brings up the Cortex-A55 clock domain.
  • Dispatches OP-TEE (BL32) into Secure EL1.
  • Hands off to U-Boot (BL33) in the Normal World.
  • Serves PSCI, including the CPU_ON that moves the boot to the Cortex-A55.
Projects · 3 of 4

TEE OP-TEE OS, BL32, Secure World kernel

What it is

OP-TEE is an open-source Trusted Execution Environment that runs in the Arm TrustZone Secure World (Secure EL1). It hosts Trusted Applications and services Secure Monitor Calls routed through TF-A BL31.

Configuration

  • Platform: qcom-monaco
  • Load address: 0x1c300000, from the FIP
  • Early TA: the Monaco PAS pseudo-TA (qcom_pas)
Role in the boot chain

BL2 loads OP-TEE from the FIP. BL31 dispatches it into Secure EL1, then continues to U-Boot.

At runtime Linux talks to OP-TEE through the CONFIG_OPTEE driver and tee-supplicant. The kernel starts the ADSP, CDSP and GPDSP through the PAS service.

Projects · 4 of 4

Linux Kernel + EL2 device tree

Build Config

  • Defconfig: arm64 defconfig (override via LINUX_DEFCONFIG)
  • Enabled: OP-TEE, KVM, EFI_ZBOOT
  • No modules: everything the board needs is built in

Command line

root=/dev/ram0 rw
console=ttyMSM0,115200 earlycon
qcom_scm.download_mode=1
EL2 Device Tree

monaco-arduino-monza.dtb with monaco-el2.dtbo applied lets Linux run at EL2.

  • The kernel has no combined EL2 DTB for this board
  • monaco.mk builds the board DTB with symbols
  • and applies the overlay with the kernel's fdtoverlay

Bundled into the UKI with the kernel and the Buildroot initramfs, no separate flash step.

Summary

Platform

  • Qualcomm QCS8275 (Monaco) on the Arduino VENTUNO Q
  • TF-A BL2 is the first open-source stage; U-Boot SPL is the option
  • The TZ image needs a QTI signature; the repo ships a signed BL2

Boot Loader Map

  • BL2 0x14680000 · BL31 0x1c200000 · OP-TEE 0x1c300000
  • U-Boot 0xaf400000 · Linux via the UKI
  • The FIP in uefi carries BL31, OP-TEE and U-Boot

Boot Sequence

  • PBL → XBL → BL2 (EL3) → BL31 (EL3 monitor)
  • BL31 starts OP-TEE (S-EL1, resident), then U-Boot (EL2)
  • U-Boot moves to the Cortex-A55 → UKI → Linux (EL2)

Projects

  • U-Boot: BL33 / UEFI, and SPL as an option
  • TF-A: BL2 and BL31, the resident EL3 Secure Monitor
  • TEE: OP-TEE OS at Secure EL1 (BL32)
  • Linux: EL2 kernel packaged as a UKI
