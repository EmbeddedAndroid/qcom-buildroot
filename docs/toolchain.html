Host Setup and Toolchains

Every board is built on a Linux host from a repo workspace, with cross compilers that the build downloads itself. This page lists what the host needs; the board pages list what is specific to each board.

Build host

A Linux x86_64 or aarch64 host with the OP-TEE build prerequisites installed. On top of those, the Qualcomm boards need:

PackageUsed for
systemd-ukifyBuilding the Unified Kernel Image (UKI) that carries the kernel, DTB, initramfs and command line
mtools, dosfstoolsCreating the FAT ESP image efi.bin and copying the UKI into it
python3 with cryptography 3.1 or newerqtestsign, cloned by the build, and the SWIV tool in qcom/security/
git, curl, unzipFetching toolchains, firmware and helper repositories during the build

Buildroot rejects PATH entries that contain spaces; the board makefiles drop them (this matters on WSL, where Windows paths end up in PATH).

repo

The sources of each board are described by a manifest in qcom-manifest and checked out with repo: 

mkdir -p ~/bin
curl https://storage.googleapis.com/git-repo-downloads/repo -o ~/bin/repo
chmod a+x ~/bin/repo

See Build System for the workspace layout repo sync produces.

Toolchains

make toolchains, run once in build/, downloads the Arm GNU Toolchain 14.3.rel1 (aarch64 and aarch32 cross compilers) and a Rust toolchain into toolchains/ next to build/. TF-A, OP-TEE, U-Boot, Linux and the Buildroot target packages are compiled with them; the host compiler only builds host tools. 

cd build
make toolchains

Flashing tools

The boards are flashed over USB in EDL (Emergency Download) mode with qdl, built from source or from a distribution package, on the host the board's USB port is connected to. See Flashing.
