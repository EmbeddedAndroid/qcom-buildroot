Flashing

All boards are flashed the same way: the board is put in EDL (Emergency Download) mode, the host loads a firehose programmer into it over USB, and the programmer writes the images to the boot storage. The board makefiles do this with qdl on the host that runs make, so the board's USB port has to be connected to that host.

EDL mode and the firehose programmer

In EDL mode the board enumerates on USB as 05c6:9008. How to get there is board specific; see the board page. qdl then uploads the firehose programmer, prog_firehose_ddr.elf from the board's Qualcomm software, and sends it the write commands.

Two ways to write

Methodqdl invocationWrites
Partition layout qdl prog_firehose_ddr.elf rawprogram<N>.xml patch<N>.xml ... Whole storage units: GPT, every partition listed with a file, and the patches that fix up the GPT. The XMLs and GPT images come with the board software or from qcom-ptool.
Partition by name qdl --storage <type> prog_firehose_ddr.elf write <label> <file> ... Only the named partitions, found by their GPT label; everything else, including the partition table, stays as it is.
